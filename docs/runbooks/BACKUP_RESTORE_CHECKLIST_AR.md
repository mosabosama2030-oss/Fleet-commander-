# قائمة تحقق النسخ الاحتياطي والاستعادة

**Task:** FC-012
**Role:** MANUS-2 — Operations & Release Engineer
**الحالة:** `PROPOSED / UNKNOWN` — لا توجد عملية Backup أو Restore منفذة بهذه المهمة.

## قواعد السلامة

- لا تنفذ هذه القائمة على Production من جلسة الوكيل.
- لا تضع dump أو credentials أو بيانات شخصية في Git أو Issue أو artifact عام.
- استخدم بيئة استعادة معزولة وبيانات منزوعة الهوية عند توفرها.
- يجب أن يوافق MOSAAB على المزود، retention، RPO/RTO، وأي إجراء إنتاجي.

## 1. تعريف السياسة قبل التفعيل

- [ ] تحديد نوع قاعدة البيانات وإصدارها — `UNKNOWN` حتى اعتماد الـstack.
- [ ] تحديد RPO المقبول بالدقائق/الساعات — `UNKNOWN`.
- [ ] تحديد RTO المقبول — `UNKNOWN`.
- [ ] تحديد backup frequency وretention — `PROPOSED`، يحتاج اعتماداً.
- [ ] تحديد موقع تخزين منفصل ومشفر — `PROPOSED`.
- [ ] تحديد مالك التشغيل ومسار التصعيد — `PROPOSED`.
- [ ] التأكد من أن تكلفة التخزين مقبولة ولا تنشئ خدمة مدفوعة دون موافقة.

## 2. فحص النسخة الاحتياطية

- [ ] تسجيل timestamp وcommit/release المرتبط.
- [ ] التحقق من نجاح المهمة من سجل المزود، لا من رسالة واجهة فقط.
- [ ] التحقق من checksum أو آلية integrity يحددها المزود.
- [ ] التحقق من encryption at rest وin transit.
- [ ] التحقق من صلاحيات أقل ما يمكن وعدم ظهور secret في logs.
- [ ] التحقق من retention وعدم وجود حذف مبكر غير مقصود.
- [ ] تسجيل النتيجة في سجل داخلي منزوعة الحساسية.

## 3. اختبار Restore في بيئة معزولة

- [ ] الحصول على موافقة صريحة قبل بدء الاختبار.
- [ ] إنشاء قاعدة Restore منفصلة وليست Production.
- [ ] استخدام نسخة منزوعة الهوية أو fixture آمن.
- [ ] حفظ وقت بدء الاستعادة ووقت انتهائها.
- [ ] تسجيل حجم النسخة دون إرفاق محتواها.
- [ ] تشغيل migration/compatibility check إن كان معتمداً.
- [ ] تنفيذ read-only smoke query.
- [ ] تشغيل Smoke Test للتطبيق على بيئة Restore إن كانت متاحة.
- [ ] قياس RTO الفعلي ومقارنته بالهدف.
- [ ] التحقق من اكتمال البيانات وفق checksum/counts غير حساسة.
- [ ] حذف بيئة الاختبار والنسخة المؤقتة وفق سياسة الاحتفاظ.

## 4. دليل القبول

يُعد الاختبار `FIXED_AND_TESTED` فقط عند توفر كل ما يلي:

- [ ] سجل مزود موثق برقم تشغيل أو مرجع غير سري.
- [ ] نسخة وSHA/digest معروفان.
- [ ] وقت الاستعادة وRTO مقاسان فعلياً.
- [ ] نتيجة integrity/read-only query ناجحة.
- [ ] Smoke Test ناجح على البيئة المعزولة.
- [ ] لا توجد أسرار أو بيانات شخصية في الأدلة.
- [ ] مراجع مستقل راجع النتيجة.

بدون هذه الأدلة تبقى الحالة `UNKNOWN` أو `NOT_RUN`، ولا يجوز إعلان أن Backup/Restore جاهز للإنتاج.

## 5. التراجع عند فشل Restore

1. أوقف الكتابة إلى بيئة الاختبار.
2. احتفظ برسالة الخطأ والمرجع الزمني دون بيانات حساسة.
3. لا تعاود المحاولة على Production تلقائياً.
4. افتح incident/Issue يصف الفشل والنسخة والـenvironment فقط.
5. صعّد إلى MOSAAB ومالك قاعدة البيانات.
6. أعد الاختبار بعد إصلاح السبب وبموافقة جديدة.

## 6. الحالة الحالية في Fleet Commander

- **VERIFIED:** توجد خطة تشغيل وإصدار مدمجة في `main`.
- **VERIFIED:** توجد Workflows لـBackend وWeb في `main` حسب الفحص الحالي.
- **UNKNOWN:** مزود قاعدة البيانات، خدمة النسخ، retention، RPO/RTO، ونتيجة Restore فعلية.
- **NOT_RUN:** لم تُنفذ Backup أو Restore أو حذف لبيانات إنتاج ضمن FC-012.
