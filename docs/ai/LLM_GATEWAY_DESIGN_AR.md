# FC-AI-01 — تصميم LLM Gateway (الحالة: PROPOSED)

- المالك: CLAUDE-1 (Backend). القرار النهائي: MOSAAB.
- الفرع: `agent/claude-1/FC-AI-01` (مبني على `agent/claude-1/VOICE-001`).
- الكود: `backend/src/ai/` (عقود + نواة Gateway + تنقيح) والاختبارات `backend/test/llm-gateway.test.ts`.
- لا يوجد مزود حقيقي ولا مفتاح ولا خدمة مدفوعة. كل شيء **مغلق افتراضيًا**.

## 1. الغرض والنطاق
نقطة عبور واحدة لأي استخدام لنموذج لغوي داخل Fleet Commander، بحيث تكون الأمان والتكلفة والخصوصية في مكان واحد، ويمكن تبديل المزود دون لمس باقي النظام.

اليوم المساعد الصوتي (VOICE-001) قواعد بلا نموذج لغوي. الـGateway **اختياري** ويضيف لاحقًا: فهم صيغ خارج القواعد، تلخيص أرقام اليوم، تصنيف المصروفات. لا شيء في المنتج يعتمد عليه.

**خارج النطاق:** اختيار مزود نهائي، Streaming، Tool/Function calling، RAG، تخزين المحادثات، أي إجراء مالي ينفذه النموذج.

## 2. القواعد الحاكمة (غير قابلة للتفاوض)
| # | القاعدة | كيف تُفرض في الكود |
|---|---|---|
| G1 | مغلق افتراضيًا وميزانية صفر | `SAFE_DEFAULT_CONFIG`؛ اختبار DISABLED وBUDGET_EXCEEDED |
| G2 | النموذج لا ينفذ: ناتجه نص أو JSON مقترح فقط | `LlmResponse` بلا حقل action؛ التنفيذ يمر بـ`VoiceSession` وتأكيد الكابتن ثم `FleetService` |
| G3 | المال والأرقام تحسبها النواة لا النموذج | النموذج لا يستلم صلاحية كتابة؛ أي رقم يقترحه يُتحقق منه بـ`asMinor`/`asKm` كأنه نطق |
| G4 | PII لا تغادر الخادم | `redact()` على كل رسالة قبل المزود؛ الغرض يحدد ما يُرسل أصلًا (مجمّع لا أسماء) |

| G6 | المفاتيح من متغيرات البيئة فقط، لا في المستودع | الـGateway لا يعرف المفاتيح؛ المحوّل وحده يقرأها |
| G7 | سقف صلب: توكنات، طلبات يومية، مهلة، حجم إدخال | تحقق + `BudgetPolicy` + قصّ `maxOutputTokens` |
| G8 | لا مزود يُفعّل دون موافقة MOSAAB | `providers: []` افتراضيًا |

## 3. المعمارية
```
 مستهلك (Voice / Insights / Expense)
        │ LlmRequest {purpose, messages, caps}
        ▼
 ┌────────────── LlmGateway ──────────────┐
 │ 1 enabled? (عام + للغرض)  → DISABLED    │
 │ 2 تحقق الطلب              → BAD_REQUEST │
 │ 3 redact (PII)                          │
 │ 4 ميزانية يومية (حجز)     → BUDGET_EXCEEDED
 │ 5 لكل مزود بالترتيب:                    │
 │     دائرة مفتوحة؟ ← تخطَّ               │
 │     مهلة (AbortController)              │
 │     فحص الناتج (فلترة/فارغ/JSON)        │
 │     خطأ قابل → التالي، غير قابل → أوقف  │
 │ 6 تسوية الميزانية + Audit               │
 └───────┬───────────────┬────────────────┘
         ▼               ▼
   LlmProvider A    LlmProvider B   (محوّلات؛ مستقبلًا)
```

## 4. الأغراض (Purposes)
| الغرض | يُرسل | لا يُرسل أبدًا | JSON |
|---|---|---|---|
| voice_understanding | نص الكلام بعد التنقيح، لغة الجلسة | موقع، اسم، لوحة سيارة | نعم (intent مقترح) |
| insights_summary | أرقام مجمّعة (يوم/أسبوع) | رحلات فردية بتوقيتاتها الدقيقة | لا |
| expense_classification | وصف المصروف + المبلغ | صور إيصالات، بيانات بطاقة | نعم |

كل غرض له: `enabled`، قائمة مزودين مرتبة، `maxOutputTokens`، `maxInputChars`.

## 5. معالجة الأعطال
| الخطأ | سلوك الـGateway |
|---|---|
| DISABLED / BAD_REQUEST / BUDGET_EXCEEDED | يرمي فورًا، لا مزود يُستدعى |
| TIMEOUT / RATE_LIMITED / PROVIDER_UNAVAILABLE / AUTH_FAILED | يجرب التالي ويسجّل إخفاقًا للدائرة |
| INVALID_OUTPUT (فارغ/JSON تالف) | يجرب التالي |
| CONTENT_FILTERED / BAD_REQUEST من المزود | يوقف: لا يُعاد الطلب على مزود آخر (قد يكون الإدخال هو المشكلة) |
| الكل فشل | `ALL_PROVIDERS_FAILED` مع قائمة المحاولات؛ **المستهلك يعود للمسار القاعدي** (الصوت يقول "ما فهمتش") |

دائرة القطع: `breaker.failures` إخفاقات متتالية تفتح المزود `cooldownMs`؛ نجاح واحد يصفّر العداد.

## 6. حقن التعليمات (Prompt Injection)
كلام السائق نص غير موثوق. الدفاع طبقي ولا يعتمد على "تعليمات قوية":
1. النموذج لا يملك أدوات ولا صلاحيات (G2).
2. أي JSON يعود يمر على قائمة بيضاء (Intent enum) وعلى مدققات الأرقام نفسها.
3. التنفيذ يتطلب تأكيدًا صريحًا من الكابتن بعد قراءة الملخص عليه (آلة الحالات الموجودة).
4. System prompt ثابت من الخادم؛ نص المستخدم يُرسل بدور `user` فقط.

## 7. القرار المقترح ADR-AI-01 (PROPOSED)
**السياق:** نحتاج إمكانية استخدام نماذج لغوية لاحقًا دون الارتباط بمزود، ودون تكلفة، وبأمان مالي.
**القرار المقترح:** اعتماد Gateway داخلي بعقود `LlmProvider`، مغلق افتراضيًا، مع الشروط G1–G8. لا مزود محدد الآن.
**البدائل:** (أ) استدعاء مزود مباشرة من كل ميزة — يشتت الأمان والتكلفة. (ب) مكتبة Gateway جاهزة — تبعية جديدة ومحجوب التثبيت حاليًا؛ نعيد التقييم عند فتح الشبكة.
**العواقب:** كود أكثر قليلًا الآن؛ تبديل مزود = محوّل واحد؛ يُلزم Persistence للميزانية قبل أي تفعيل.

## 8. فئات المزودين (دون اختيار)
لم أتحقق من أسعار أو حدود مجانية حالية، فالقيم **UNKNOWN** حتى تُراجَع من مصدر رسمي.
| الفئة | ميزة | مخاطرة | الحالة |
|---|---|---|---|
| API مستضاف بطبقة مجانية | بلا تكلفة ظاهرة للتجربة | الحدود والشروط وخصوصية البيانات UNKNOWN؛ قد تتغير | UNKNOWN |
| API مدفوع | جودة ثابتة | يتطلب موافقتك (G8) | غير مسموح الآن |
| نموذج محلي (Ollama أو مثله) | لا بيانات تخرج، لا تكلفة API | يتطلب عتادًا؛ الاستضافة DEC-08 غير محسومة | PROPOSED للتطوير فقط |

## 9. الأدلة (Evidence)
- `node --test "test/**/*.test.ts"` → 119 اختبارًا، 119 ناجحًا، 0 فاشل (24 منها للـGateway).
- `tsc --noEmit` → exit 0.
- فحوص طفرة (كسر الكود عمدًا ثم تأكد أن الاختبارات تفشل): 6 من 6 قُتلت — السماح بالـfallback على BAD_REQUEST، تعطيل التنقيح، تعطيل الميزانية، عدم فتح الدائرة، تجاهل DISABLED، عدم قصّ maxOutputTokens.
- الحالة: **FIXED_AND_TESTED** للنواة والعقود. **NOT_RUN**: أي مزود حقيقي، أي اختبار شبكة.

## 10. الفجوات والمخاطر
1. **الميزانية في الذاكرة:** إعادة تشغيل الخادم تصفّرها فتتجاوز السقف. شرط قبل أي تفعيل: حفظها (يعتمد DEC-08 قاعدة البيانات).
2. **التنقيح محدود:** يلتقط بريدًا وهاتفًا وأرقامًا طويلة وإحداثيات؛ لا يلتقط أسماء أو عناوين نصية حرة (INFERRED). الدفاع الأول هو ما يُرسل أصلًا.
3. تقدير التوكنات محافظ (حرف = توكن) وقد يرفض طلبات سليمة قرب السقف.
4. لا Streaming ولا اختبار حِمل ولا تقييم لجودة العربية/العامية.
5. التنقيح يحوّل الأرقام الهندية (٠-٩) إلى لاتينية في ما يُرسل — مقصود.
6. لم تُراجَع الوثائق الأحدث على `main` بحثًا عن قرارات AI سابقة؛ لم أجد FC-AI-01 في الفهرس ولا في Issues.
