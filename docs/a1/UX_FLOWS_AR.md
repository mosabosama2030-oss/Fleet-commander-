# تدفقات الواجهة — A1-07/08 (مسودة PROPOSED)

مبادئ: عربي RTL (NFR-012)؛ لا رسالة نجاح قبل تأكيد الخادم (NFR-003)؛ واجهة Web متجاوبة وAndroid بنفس عقد API (FR-015)؛ مستخدم يعمل أثناء القيادة فالإدخال قصير وبأزرار كبيرة. شاشات المال تنتظر DEC-02/03.

## الشاشات
| الشاشة | الغرض | حالات |
|---|---|---|
| دخول | FR-001 | خطأ موحد، تأخير بعد محاولات، استعادة |
| الرئيسية | الشيفت الحالي أو «ابدأ شيفت» | لا شيفت / OPEN / خطأ اتصال |
| بدء شيفت | اختيار المركبة + عداد البداية (+صورة اختيارية) | مركبة واحدة تُختار تلقائيًا إن اعتمد DEC-01(أ) |
| أثناء الشيفت | إضافة مصروف سريع، (إيراد/رحلة حسب DEC-02)، إنهاء | حفظ جارٍ / فشل مع إعادة محاولة |
| إنهاء شيفت | عداد النهاية + مراجعة الملخص + تأكيد | عداد أقل من البداية، شيفت مغلق |
| سجل الشيفتات | FR-009 | فارغ، تحميل، ترقيم |
| تقرير فترة | UC-03 | فترة غير صالحة، لا بيانات |
| المركبات | FR-003 | حسب DEC-01 |
| الإعدادات | الملف والمنطقة الزمنية وتصدير | |

## سلوك الإرسال (موحد)
1. زر الإرسال يتعطل ويظهر «جارٍ الحفظ».
2. يُولَّد `Idempotency-Key` مرة لكل نية وليس لكل نقرة.
3. عند timeout: «لم نتأكد من الحفظ» + زر «تحقق/أعد المحاولة» بنفس المفتاح.
4. النجاح فقط بعد استجابة 2xx.

## عرض القيم
«إيراد مسجل» لا «صافي ربح» قبل اعتماد المال؛ كل رقم بوسم فعلي/مقدّر/غير معروف.
